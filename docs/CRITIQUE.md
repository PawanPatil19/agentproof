# Critique of the AgentProof handoff (v1.0, 19 Oct 2026)

The handoff is unusually disciplined: it refuses "trust scores", separates
check results from actions, admits that traces cannot stop side effects, and
defers hosted infrastructure until someone values the receipts. Most of it
survives scrutiny. This note covers what doesn't, and the decisions this
repository makes in response.

## What is strong — keep it

- **Results ≠ actions.** `pass / fail / unknown / not_applicable` feeding a
  policy that chooses `allow / block / review` is the right shape. It makes
  observe mode trivial (compute the decision, don't apply it) and keeps
  uncertainty visible instead of rounding it to "pass".
- **Enforcement beside the app, explanation exported.** Local-first is both the
  privacy story and the latency story.
- **Honest vocabulary.** "Verified" = "passed recorded checks under a named
  policy". The product guardrail against a "safe agent" badge is worth
  protecting as the company grows.
- **Exit gates per phase** rather than dates.

## Where the plan is weak

### 1. Reference integrity alone catches the wrong failures

The deterministic checks listed for v1 — missing IDs, unknown IDs, empty
excerpts, malformed URLs — mostly catch *plumbing bugs*. The failure in the
handoff's own first example ("links to a real article that never says that")
sails straight through them: the ID resolves, the excerpt is non-empty.
Semantic support is pushed to an opt-in model judge, so the flagship pain is
unsolved by the free, local, deterministic tier.

**Decision:** make **quote grounding** a first-class deterministic check. A
claim may carry a `quote`; the verifier requires that the normalized quote
appears verbatim in the captured content of one of the claim's cited evidence
records (with a minimum length so "the" can't ground anything). This is cheap,
explainable, has near-zero false positives, and catches the most common
fabrication pattern — a plausible quote attributed to a real source. It still
does not prove the claim follows from the quote, and the report says so.

### 2. "Zero-config" is oversold; the real cost is the claims envelope

Nothing is checkable until the agent emits structured claims with evidence IDs.
That is the true onboarding cost, and the handoff mentions it only in a footnote
("material claim extraction requires explicit structured claims in v1").

**Decision:** treat the envelope as a product surface. `output.claims[]` is the
single convention; `agentproof init` writes a policy whose `output_schema` *is*
the instruction you give the model; the example shows the shape end to end.
Automatic claim extraction stays out of v1.

### 3. Two-party "acceptance" between in-process agents is mostly bookkeeping

When coordinator and worker are two prompts in the same process, a worker
"accepting a digest" proves nothing cryptographically — the host plays both
roles. The genuinely useful parts are narrower:

- **digest pinning** — the obligations validated at completion are exactly the
  ones issued, so a retry or edited policy can't silently weaken them;
- **attempt identity** — duplicate/late completions are detectable;
- **trusted identity at the guard** — the tool guard takes identity from the
  host's closure, never from the worker's arguments.

**Decision:** implement all three, but describe the lifecycle honestly as
*integrity and replay protection inside a trusted host*, not authentication.
Real cross-trust-boundary binding (signed contracts, per-worker credentials)
is a later, gateway-era feature.

### 4. The v1 storage stack is heavier than v1 needs

SQLite, encrypted snapshots, a worker pool, and OTel are all on the Phase 1–2
path. None are needed to prove the core value (a readable receipt that
explains a blocked handoff).

**Decision:** receipts are versioned JSON files written `0600` into a reports
directory, plus a `prune` command for retention. Snapshot storage, SQLite, OTel
and MCP are explicitly deferred. Swapping the `ReceiptStore` interface later is
cheap.

### 5. Privacy default conflicts with a useful report

"Metadata and hashes only" by default is right for the receipt, but a report
that only shows `sha256:…` per claim won't sell a 10-minute first run.

**Decision:** split the artifacts. The **receipt** (the thing that gets
exported or shipped to a dashboard) is metadata-only by default: claim text and
evidence bodies are replaced by hashes, URL query strings are stripped,
obvious secrets are redacted. The **local HTML report** generated by
`agentproof inspect` from a file the developer already holds may show claim
text, is written `0600`, and says so in its footer.

### 6. Under-specified policy semantics

The sample policy mixes check configuration, per-check unknown handling
(`unknown_source_date: review`) and global enforcement. With several such
knobs the effective behaviour becomes hard to predict.

**Decision:** one rule for every check: *a configured check is required; a
required fail → `on_required_check_fail`; a required unknown →
`on_required_check_unknown`; checker crash → `on_verifier_error`.* To keep a
check visible but non-blocking, list it under `enforcement.advisory_checks`.
Unknown keys anywhere in the policy are rejected.

### 7. Should a blocked tool call also fail the deliverable?

The handoff blocks a forbidden tool before invocation but doesn't say what
happens to that worker's output. **Decision:** yes — an attempt that tried a
forbidden tool fails `tools.permission` at completion. A worker that tried to
publish during a drafting task should not have its draft consumed silently.

### 8. Market risk is under-weighted

Guardrail libraries, RAG evaluators (faithfulness/groundedness metrics) and
agent observability tools each cover a slice. The handoff calls its
differentiation a hypothesis, which is correct; the risk is that "receipt +
contract" is a feature those tools add in a quarter. The defensible wedge is
**the boundary**: a framework-independent envelope that a coordinator refuses
to consume without a passing receipt. The reference two-agent app should make
that refusal the hero moment — so in `examples/research-handoff` it is.

### 9. Smaller issues

- Exit code `2` for both *block* and *review* loses information in CI; this
  implementation keeps `2` for block/review per the spec but prints which.
- `max_source_age_days` needs a reference time; replays must not drift. The
  verifier uses the run's `submitted_at`, never wall-clock, when present.
- Numeric fidelity needs units, or `4.2` (millions) "matches" `4200000`. Unit
  mismatch is its own reason code.
- `javascript:` locators would be an XSS vector in any report; locators are
  scheme-checked and all report text is escaped.
- The 8–10 week estimate is plausible for the local core only if Phase 0
  interviews don't slip; the MCP gateway alone is a multi-week security
  project and is correctly fenced off.

## What this repository therefore contains

The local v1 slice (Phases 1–2 of the handoff), nothing hosted:

| Area | Status |
| --- | --- |
| Deterministic checks: schema, references, quote grounding, content hash, source allowlist, freshness, numeric fidelity, URL safety, tool permissions, deadline, contract binding | ✅ |
| Policy compiler (strict YAML, digests, registry cross-refs) + presets | ✅ |
| Decision engine with observe / enforce, advisory checks | ✅ |
| Metadata-only receipts with digest, local HTML report | ✅ |
| SDK: contract issue / accept / retry, tool guard, completion & final-answer gates, output-bound review approvals | ✅ |
| CLI: `inspect`, `check`, `report`, `init`, `policy validate`, `prune` | ✅ |
| Two-agent reference example, fixture suite, benchmark | ✅ |
| Semantic judge, MCP gateway, OTel export, hosted dashboard, Python SDK | ⏭ deferred |
